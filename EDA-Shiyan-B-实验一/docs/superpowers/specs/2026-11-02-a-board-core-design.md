# A 部分板级核心设计

## 意图

补齐 A 负责的实验二底层数据依赖，使 B/C 可在稳定的 Board、几何、板文件和网络模型上继续工作。文件格式严格采用仓库 `DECISIONS.md` D4.1、D4.3、D4.5；板框使用 D5 规则；走线、过孔和覆铜 ID 使用 D6 规则。

## 范围

- 定义板层组、板层、实例、走线、过孔、覆铜、网络和引脚引用模型。
- 提供 Board 的 track/via/pour ID 分配、按 ID 插入和删除。
- 提供通用简单多边形、面积、点包含和线段几何函数，单位为 mil。
- 提供 D4.6 封装局部/板世界正反坐标变换和底面层映射。
- 实现 `EDA-BRD 1` 的编码、解码、文件载入和原子保存。网络清单作为板文件的 `net` 记录解析，不新增独立网表文件格式。
- 对内部引用做严格校验；载入时以 Footprint resolver 校验板实例所用封装及网络引脚编号。

## 不包含

- GUI、`DocumentContext`、`ITool` 和服务接口（由 B 提供）。
- 制造规则、DRC、封装模板及 BoardOutlineTool（由 C 提供）。
- 自动布线、覆铜重算、复杂多边形布尔运算或独立 `EDA-NET` 格式。

## 方案比较

1. 将板模型、解析器和 UI 服务放在一起：实现快，但会让 core 依赖尚未交付的 B/C 接口。
2. core 只负责 Board 数据、几何和 `EDA-BRD 1`，外部封装通过小型 resolver 回调传入：依赖边界清晰，能先独立交付；调用端需要提供同步查找函数。**采用此方案。**
3. 先只写 Board 结构、不做序列化：可提前让 C 开始算法，但无法闭环验证文件约定，也不能满足 A 的文件格式职责。

## 接口与规则

- 所有模型长度、坐标均为 mil；板世界坐标 X 向右、Y 向上。
- `Track`、`Via`、`CopperPour` 首字段分别为 `TrackId`、`ViaId`、`PourId`；ID 由 Board 单调分配，0 为无效值，删除不回收分配序号。显式插入保留传入 ID，允许撤销命令以原 ID 恢复对象。
- Board 解析不依赖 UI；`FootprintResolver` 同步返回一个拥有的 `Result<Footprint>` 值，避免借用对象生命周期问题。resolver 缺失封装或网络引用不存在的引脚时，载入整体失败。
- 结构校验覆盖格式必需项、唯一 ID/名称、引用、正向尺寸、层类型、过孔层约束和简单非零板框/覆铜多边形；生产工艺规则仍归 C。
- 底面变换按先镜像局部 X、再逆时针旋转、最后平移执行；逆变换按逆序撤销。底面顶/底铜、丝印、阻焊互换，板框与自定义层保持原 ID。
- 文件记录允许前向引用，文件完成后统一校验。板框载入后统一为逆时针；保存输出逆时针坐标。
- 解析错误包含行号，UTF-8/LF，拒绝未知记录、非法数字、错误数量、缺失 `end` 及 `end` 后数据；保存使用 `QSaveFile`。

## 未决的外部接入

B 尚未交付 `DocumentContext` / `ITool` / `app/services.h`。本设计不预设这些接口；Board core 通过纯值模型和 `core/io.h` 暴露，不直接依赖 app/render。C 的 `validation.h` 提案需由 A/C 单独确认，不纳入本次擅自定稿。
